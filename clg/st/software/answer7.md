## ✏️ Paper 7 — Q2(a) [6] | BVA and ECP
### 🔢 Answer
*Same as Paper 2 Q1(b).* ECP: group inputs into equivalence classes, test one from each. BVA: test at boundary edges (min-1, min, min+1, max-1, max, max+1). ECP reduces test cases. BVA catches boundary bugs. Use together for best results.
<!-- END OF QUESTION P7-Q2(a) -->

## ✏️ Paper 7 — Q6(a) [6] | Manual Testing Process
### 🔢 Answer
**Manual Testing Process — Steps:**

**1. Requirement Analysis** — Study requirements (SRS, user stories). Understand WHAT needs to be tested. Identify testable requirements. Clarify ambiguities with stakeholders.

**2. Test Planning** — Create test plan: scope, objectives, strategy, schedule, resources, tools, entry/exit criteria, risk analysis.

**3. Test Case Design** — Write test cases based on requirements: Test Case ID, Description, Pre-conditions, Steps, Input Data, Expected Result, Priority.

**4. Test Environment Setup** — Prepare the environment: install software, configure databases, set up test data, verify environment matches requirements.

**5. Test Execution** — Execute test cases manually: follow each step, enter inputs, observe actual results, compare with expected results. Mark: PASS (match) or FAIL (mismatch).

**6. Defect Reporting** — For FAILed tests, log defects in bug tracking tool (Jira): Title, Steps to Reproduce, Expected vs Actual, Severity, Priority, Screenshots, Environment.

**7. Defect Tracking & Retesting** — Track defect status: New → Assigned → Fixed → Retest → Closed/Reopened. Retest fixed defects. Run regression tests.

**8. Test Closure** — Generate test summary report: total cases, passed/failed/blocked, defect summary, coverage %, recommendations, sign-off.

```
[Requirement Analysis] → [Test Planning] → [Test Case Design]
    → [Environment Setup] → [Execution (PASS/FAIL)]
    → [Defect Reporting (Jira)] → [Retesting + Regression]
    → [Test Closure Report]
```
<!-- END OF QUESTION P7-Q6(a) -->
