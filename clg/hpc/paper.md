```
│  2. All-to-All Broadcast (Ring/Mesh/Hypercube)    [ALL 5 papers]│
│  3. Scatter & Gather                              [ALL 5 papers]│
│  4. Circular Shift (Ring/Mesh/Hypercube)          [ALL 5 papers]│
│  5. Prefix-Sum Operation (Hypercube)              [ALL 5 papers]│
│  6. All-to-One Reduction                          [4/5 papers]  │
│  7. Blocking/Non-Blocking MPI Communication       [3/5 papers]  │
└─────────────────────────────────────────────────────────────────┘
```

#### Key Points to Remember:
- **One-to-All Broadcast**: Uses recursive doubling; on Ring, Hypercube, Mesh
- **All-to-All Broadcast**: Every node sends to every other node; cost analysis important
- **Prefix-Sum**: Hypercube-based algorithm; parallel reduction pattern
- **Circular Shift**: On Ring, Mesh, and Hypercube topologies
- **Scatter**: One source → all nodes (different data)
- **Gather**: All nodes → one destination (collection)
- **Blocking**: MPI_Send / MPI_Recv (waits for completion)
- **Non-Blocking**: MPI_Isend / MPI_Irecv (proceeds without waiting)

```
└─────────────────────────────────────────────────────────────────┘
```

#### Key Points to Remember:
- **Performance Metrics**: Speedup (S=T_s/T_p), Efficiency (E=S/p), Cost (C=T_p×p)
- **Granularity**: Fine-grained (small tasks, high communication), Coarse-grained (large tasks, less communication)
- **Sources of Overhead**: Interprocess communication, idle time, extra computation, synchronization
- **Matrix Multiplication**: Block decomposition; row-wise and column-wise partitioning
- **Isoefficiency**: Measures scalability; W = KE p f(p) where f(p) is overhead function
- **Amdahl's Law**: S ≤ 1/(f + (1-f)/p) where f is serial fraction
- **Gustafson's Law**: S = p - f(p-1) — focuses on scaled speedup

```
└─────────────────────────────────────────────────────────────────┘
```

#### Key Points to Remember:
- **CUDA Architecture**: SM (Streaming Multiprocessors), SIMT execution model
- **Memory Hierarchy**:
  - Global Memory → Shared Memory → Registers → Constant/Texture Memory
- **Thread Hierarchy**: Thread → Block → Grid
- **Processing Flow**: CPU code → Launch kernel → GPU executes → Results back to CPU
- **Key Functions**: cudaMalloc, cudaMemcpy, cudaFree, cudaDeviceSynchronize
- **Kernel Launch**: `kernel<<<gridDim, blockDim, sharedMem, stream>>>(args)`
- **Key Terms**:
  - **Host**: CPU and its memory
  - **Device**: GPU and its memory
  - **Kernel**: Function executed on GPU
  - **Device Code**: Code running on GPU

#### Key Points to Remember:
- **Odd-Even Transportation Sort**: Alternating odd-even phases; n phases total; O(n) parallel time
- **Parallel Merge Sort**: Divide array, sort in parallel, parallel merge; O(n log n / p) time
- **Parallel BFS**: Level-synchronous approach; frontier expansion in parallel
- **Parallel DFS**: Work stealing; harder to parallelize than BFS
- **Kubernetes**: Container orchestration; features: auto-scaling, self-healing, load balancing, service discovery
- **Issues in Parallel Sorting**: Load balancing, comparison operations, data movement, communication overhead
- **GPU Applications**: Deep learning, image processing, scientific simulations, cryptocurrency mining
